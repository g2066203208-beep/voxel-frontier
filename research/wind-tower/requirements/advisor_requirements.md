## 1. 题目与研究范围

导师要求不是“把标题改得好听”，而是要求**每个关键词都可定义、可验证、与全文工作量一致**：

1. 模糊形容词必须消除或给出严格边界，例如“极端”“超高”“动力作用”不能只凭直觉使用。
2. “混塔”必须说明是哪一种混塔：本文应明确为**下部预应力钢筋混凝土、上部钢塔的材料型混合塔架**。
3. 风和地震不要为了“内容多”硬塞进一篇硕士论文。应选择一条主线并做透。
4. “动力响应”是研究过程，不是论文终点；必须回答动力响应之后用于识别什么问题、评价什么性能、如何服务优化。
5. “结构优化”必须有明确的问题来源、目标、约束和验证，不能最后突然增加一个优化章节。

### 当前落实
- 当前路线已明确选择**抗风**，不再设置风—震联合生产路线。
- 工作题目已经删除“极端动力”“超高”等模糊词。
- “抗风性能”与“结构优化”仍是**CONDITIONAL**：只有第四章形成明确性能指标、第五章形成有依据设计空间、第六章完成独立回算后才能最终PASS。

## 2. 模型来源与学术可复现性

导师明确强调：

1. 学术研究优先使用**公开、主流、可复现、第三方可对比**的模型，而不是资料不完整的商业工程案例。
2. 应广泛检索国际期刊，识别该方向大家反复使用/引用的基准模型或代表模型。
3. 如果使用实际工程塔，只有设计资料还不够；还应有动力特性、试验或第三方验证资料，否则评委无法判断模型是否正确。
4. 工程项目可以作为背景，但不能把一个资料不足的商业项目直接包装成“通用学术基准”。

### 当前落实
- 上部机组采用 DTU 10 MW 官方参考机组，具备公开可复现一级来源。
- 下部混塔几何以何泽瑜 2024 学位论文为原型来源，正在通过国际期刊/高质量期刊进行横向校核。
- 已专门建立 `baseline_identity.tsv`，区分“参考机组、原型塔、Abaqus实现、OpenFAST实现、相关但不同的模型”。
- **仍需继续做“国际期刊中混塔基准模型复用情况”专项检索**，不能只因为何泽瑜模型可获得就自动宣布为最佳学术基准。

## 3. 工程背景

导师要求：
1. 不得凭想象补工程信息。
2. 如果采用工程背景，优先采用已有真实资料的嘉鱼项目。
3. 场址边界条件可以围绕真实项目展开，但论文研究不必等同于企业设计咨询。
4. 工程背景和学术基准必须分开：**真实场址负责背景与环境输入，公开参考模型负责可复现研究对象**。

### 当前落实
- 嘉鱼项目只承担真实场址背景、长期风况与工程语境。
- 不把嘉鱼 200 MW 项目批复解释为“本文存在真实10 MW工程机组”。
- ERA5与IEC风况的角色已分开。

## 4. 参数来源

导师要求非常明确：**不能自己拟。**

每一个关键参数至少属于以下一种来源：
- 标准/规范；
- 官方软件或参考机组；
- 实际工程技术资料；
- 同类高质量论文/试验；
- 自己通过可复现公式或试验反演得到。

如果以上都没有，参数必须标记为HOLD，不能悄悄取“常用值”。

### 当前落实
- 已建立 `parameter_registry.tsv`。
- CDP、预应力、连接、阻尼、风场、疲劳、优化变量均按参数账本逐项闭合。
- “常用值”“经验取值”不能直接进入最终论文。

## 5. 简化模型必须回答“为什么”和“影响多大”

导师特别指出：
1. “为了节省计算资源”不能成为2026年的充分理由。
2. 必须查最新文献，看当前研究如何做等效/简化。
3. 简化前后必须有影响评估；如果简化对响应影响很大，后续结论就失去基础。
4. RNA不能只用总质量相等证明等效，还应考虑空间分布、质心、转动惯量和作用点。

### 当前落实
- RNA验证已经升级为质量—质心—惯量—6×6空间质量矩阵的层级验证。
- 但当前正式输入尚未完全回库，故该项继续HOLD，不能只引用历史误差数字宣布完成。

## 6. “模型建立与验证”应先闭合，再进入响应分析

导师要求：
- 第二章应解决“模型怎么建、依据是什么、模型是否可信”；
- 后续章节才基于验证后的模型做响应、机制和优化；
- “模型建立与分析”不能把生产分析和验证混在一起。

### 当前落实
当前新结构为：
**第二章：模型+验证 → 第三章：风场/整机载荷 → 第四章：结构响应/机制 → 第五章：敏感性 → 第六章：优化。**

## 7. 风工况术语必须严格

导师明确提醒：
1. “极端风”含义很宽，可能包括台风、下击暴流、龙卷风等特殊风。
2. 仅仅风速较大不能随意称为“极端风”。
3. 重现期/设计寿命/设计工况要有标准依据。

### 当前落实
- 正文不笼统写“极端风”。
- 使用 IEC NTM、ETM/DLC 等标准工况身份。
- 台风、龙卷风、下击暴流明确排除在本文范围外，除非后续新增专门模型和文献证据。

## 8. 风—震问题不要简单叠加

导师指出：
- 风是长期随机作用，地震是偶遇作用；
- 不能简单把两个极端时程同时施加就称为“耦合”；
- 若研究震后风或风损后震，必须有损伤状态、发生顺序和概率逻辑。

### 当前落实
**本文正式路线只做抗风，不再设置风—震联合生产章节。**

## 9. 优化必须由薄弱问题驱动

导师要求的完整逻辑是：

**文献/响应分析发现问题 → 确认薄弱位置/控制机制 → 选择能改变该机制的变量 → 敏感性筛选 → 明确目标和约束 → 优化 → 用原高保真模型回算。**

优化目标不能无限增加；安全性、经济性、耐久性不是同一问题，必须明确本文主要目标。

### 当前落实
- 第四章目标是识别控制部位与机制；
- 第五章才从机制反推变量；
- 第六章才定义多目标优化；
- 成熟优化算法本身不作为创新点。

## 10. 论文各章必须“承上启下”

导师要求：
- 每章开头要说明输入问题；
- 每章结尾要像一个小摘要，总结得到什么；
- 明确本章输出如何成为下一章输入；
- 不能把章节写成互不相关的工作堆积。

### 当前落实
MASTER已采用：
**问题 → 输入 → 方法 → 证据 → 输出 → Gate → 下一章输入**。

## 11. 创新点

导师要求：
- 创新点要尽早收敛；
- 两个核心创新点要能把全文串起来；
- 不能等所有计算完成后再从结果里硬找“创新”。

### 当前候选
目前只能保留“候选创新”，不提前定稿：
1. **可信跨模型载荷—结构证据链及对象化验证**；
2. **随机风控制工况下薄弱机制识别→机制驱动优化闭环**。

是否最终成立，必须由第四至第六章真实结果决定。

## 12. 进度管理与汇报

导师要求：
1. 主动、定期汇报，建议约半个月一个周期；
2. 每轮都要有“完成了什么 / 未完成什么 / 当前困难 / 下一步计划”；
3. 发现问题本身就是研究进展，不能为了“看起来完成”隐藏HOLD；
4. 每项任务有完成时间和勾选状态；
5. 同时管理论文成果、专利/软著/论文投稿等研究产出。

### 当前落实
- GitHub已建立 task_registry / EXECUTION_STATUS / issue ledger；
- 2026-10-09进展汇报单独设T021；
- 所有HOLD有关闭条件，不再口头说“差不多”。

## 13. 本清单的强制作用

从本文件建立以后，任何新方法、参数、章节、优化变量或生产工况都必须先问：

1. **对应哪条导师要求？**
2. **依据是什么？**
3. **为什么用这个方法而不是其他方法？**
4. **要得到什么结果？**
5. **结果如何进入下一步？**
6. **怎么验证？**

答不上来，不进入正式论文生产路线。
