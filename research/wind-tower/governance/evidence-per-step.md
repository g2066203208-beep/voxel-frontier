# 每一步研究工作的依据与验收规则

生效日期：2026-10-04。来源：用户明确要求每一步参考期刊、学位论文等可靠资料，并在 GitHub 保存全过程。本文件是本研究的工作规则，不冒称某篇文献或规范的原文要求。适用于选题、综述、建模、参数、计算、后处理、图表、创新和结论。

## 每一步必须留下的记录

| 项目 | 必须记录的内容 |
|---|---|
| 研究问题 | 本步解决的问题、对应章节和老师问题编号、需要检查的目标量。 |
| 方法依据 | 作者、题名、年份、期刊或学位授予单位、DOI或稳定链接，实际使用的章节、页码、公式或图表。 |
| 实际阅读 | 区分元数据、摘要、已读方法节、已读结果节、全文；获取了 PDF 不等于读完。没有读到的段落不作为已核依据。 |
| 支持范围 | 文献为什么适合本步，其机组、材料、几何、边界、荷载和求解方法与本研究有什么差别；明确不能支持的结论。 |
| 参数来源 | 原工程对象或数据文件、版本、SHA-256、字段、单位、坐标和适用范围；文献参数保留原始定位。没有来源的参数列为待解决。 |
| 推导与假设 | 自行推导单列公式和量纲检查，引用基础理论；作者提出的设计、候选创新和工程假设明确标记，不能伪装成文献结论。 |
| 事前验收 | 目标量、对照模型、工况、误差定义、预算与理由，冻结时间戳、原输入 SHA 和登记编号。区分规范限值、文献作者使用的阈值、本研究数值精度目标；禁止看完结果后改阈值取得 PASS。 |
| 实际执行 | 脚本版本、输入哈希、软件版本、运行编号、输出哈希、真实状态、独立核对及失败原因。方案、数据生成、成功终止、数值验证、物理验证分别记录。 |
| 结论边界 | 依据和数据共同支持的结论、未关闭问题、是否允许进入下一步；未做的实验不得写成已完成。 |

一条方法依据可以支持多个明确对应的步骤，但每个步骤仍需给出引用位置及适用性，不能只在章末堆参考文献。

## 来源选择与使用

1. 优先读与问题直接相关的原始期刊研究、官方参考机组数据、理论与软件原始文档；规范应核对适用版本和实际可读条文。
2. 学位论文可用于追溯建模细节、原始工程和方法推导，须记录授予单位、年份、章节页码及可获取来源。论文的摘要、目录或二次引用不能证明具体参数已核实。
3. 不设期刊、学位论文等类别的凑数指标。相关来源的质量、实际阅读和可检验性优先。不能拿另一台机组的结果百分比当作本模型误差。
4. 官方软件文档支持单元、约束、算法和 API 的含义，不提供本叶片的真实厚度、铺层、材料或实验标定结果。
5. 新文献进入主表后，仍须完成与本步有关的阅读、适用性判断及方法记录更新；频繁更新主表不自动改变已完成工作的验证状态。
6. 软件文档记录产品/版本、访问日期和实际读到的段落；随主分支变动的在线文档在执行前固定对应版本或内容哈希，并核对真实运行版本。当前 RNA 尚未运行的候选实现不得借当前文档自动标为软件配置已验收。

## GitHub 和私有文件的边界

公开原创研究思路、逐步骤方法与来源、问题整改、模型输入、执行脚本、数据、失败记录、结果和中文科学图。论文正文/修订 Word、老师讨论 Word 及转录、受限文献全文与摘录不上传。对老师问题使用原创问题摘要；研究方案和结果不得复制成公开论文正文。

来源主表、逐步骤方法表、运行表和状态说明应相互对应。每次发布从最新主分支更新，保留持续文献更新。第二章当前为阶段稿；只有相应科学问题与图文验收完成，才记录该范围内的完成状态。
